# Marker.io -> GitHub bridge

This project synchronizes Marker.io tasks into GitHub issues so you can automate customer intake and issue tracking in your repository.

## Configuration

1. Copy `.env.example` to `.env`
2. Fill in the values:

```env
MARKER_BASE_URL=https://api.marker.io
MARKER_TASKS_URL=
MARKER_WORKSPACE_ID=
MARKER_API_KEY=
MARKER_AUTH_MODE=api_key
MARKER_COOKIE=

GITHUB_OWNER=your-user
GITHUB_REPO=your-repo
GITHUB_TOKEN=ghp_...
GITHUB_API_URL=https://api.github.com
GITHUB_LABEL=markerio

DRY_RUN=false
REQUIRE_CONFIRMATION=false
```

## How to use it

### Option 1: base URL + workspace

If you only have the Marker domain and a workspace, use:

```env
MARKER_BASE_URL=https://api.marker.io
MARKER_WORKSPACE_ID=your-workspace-id
MARKER_API_KEY=your-token
MARKER_AUTH_MODE=api_key
```

### Option 2: exact tasks URL

If your instance or endpoint already returns the task list directly:

```env
MARKER_TASKS_URL=https://api.marker.io/v1/tasks
MARKER_API_KEY=your-token
MARKER_AUTH_MODE=api_key
```

### Option 3: cookie

```env
MARKER_COOKIE="session=...; other=..."
MARKER_AUTH_MODE=cookie
```

## Running it

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python sync.py
```

If you set `REQUIRE_CONFIRMATION=true`, a window will appear showing the pending changes before writing to GitHub. Click **Apply Changes** to confirm, or **Cancel** to abort without making changes. With `false`, synchronization runs automatically.

## Windows executable

To create a standalone executable, run `build.bat` from Windows. It creates `dist\MarkerGitHubBridge.exe` and copies `.env.example` to the same folder.

Before sharing or running the executable, copy `dist\.env.example` to `dist\.env` and configure it there. The executable reads `.env` from its own folder, so credentials are never bundled into the `.exe`.

## Dedupe

The `marker_id` is used inside the issue body to detect tasks that were already created. Synchronization does not duplicate issues if the field already exists.

Tasks whose Marker.io workflow state is `closed` (or `archived`) are created and closed automatically in GitHub.
The original Marker.io description and dates are added to the issue body.

Each run reconciles all Marker.io tasks with the issues created by the bridge in GitHub. It only creates or updates issues whose title, body, or state changed.

## Daily schedule

You can run it with Windows Task Scheduler or cron every day.

PowerShell example:

```powershell
cd C:\ruta\markerio-github-bridge
.\.venv\Scripts\Activate.ps1
python sync.py
```

## Test repository cleanup

To list issues generated by this bridge without modifying anything:

```bash
python cleanup_test_issues.py
```

To permanently delete them after reviewing the list:

```bash
python cleanup_test_issues.py --delete --confirm
```

The script only considers issues that contain both `marker_id:` and this bridge signature; it never deletes pull requests.

## Recommendation

If Marker exposes multiple authentication methods for your account, always prefer the more stable option:

- `MARKER_API_KEY` for API key authentication
- `MARKER_COOKIE` only if the web session is required

## Note

This project is intended as a base. If your Marker instance requires a specific response shape or different endpoint, change `MARKER_TASKS_URL` or adapt `marker_client.py` to match the exact format.
